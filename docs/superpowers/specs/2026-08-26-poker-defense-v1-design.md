# Poker Defense v1.0 Design

**Status:** Approved  
**Date:** 2026-08-26  
**Product promise:** 포커의 기대감과 타워 디펜스의 누적 압박을 15분 안에 반복해서 즐기는 싱글플레이 웹게임.

## Goals

- 첫 플레이어가 별도 설명 없이 카드 교환, 족보 확정, 배치, 전투를 시작한다.
- 낮은 등급 유닛도 합성 재료가 되어 모든 라운드의 보상이 의미 있다.
- 10라운드마다 유물 선택으로 판마다 다른 빌드가 만들어진다.
- 동일한 데일리 시드로 매일 공정하게 점수를 비교할 수 있다.
- 최고 기록, 업적, 설정이 브라우저에 안전하게 보존된다.
- 기존 결정론 코어와 헤드리스 시뮬레이터 구조를 유지한다.

## Run Structure

기존 60라운드 `prep → combat` 루프를 유지한다. 준비 단계에서는 카드 교환, 족보 확정, 유닛 배치·이동·판매·합성, 강화, 유물 선택을 수행한다. 전투 중에는 배속과 일시정지만 허용하고 경제·배치 상태는 바꿀 수 없다.

10, 20, 30, 40, 50라운드를 마친 뒤 다음 준비 단계에서 세 유물 중 하나를 선택한다. 선택 전에는 다음 전투를 시작할 수 없다. 유물 후보는 게임 시드와 마일스톤으로 결정되어 리플레이와 데일리 런의 공정성을 보존한다.

## New Strategic Systems

### Unit fusion

준비 단계에서 동일 등급 유닛 3기를 합치면 한 단계 위 유닛 1기가 된다. 결과 유닛은 첫 번째 재료 위치에 생성된다. 신룡은 합성할 수 없다. 이 규칙은 필드 상한에서 생기는 정체를 해소하고 낮은 족보의 장기 가치를 만든다.

### Relics

- 왕가의 인장: 전체 피해 +12%
- 전쟁 금고: 처치 골드 +25%
- 복리 장부: 라운드 이자 +50%, 이자 상한 +20G
- 증축 허가증: 필드 패배 상한 +10
- 재빠른 손놀림: 매 라운드 두 번째 교환까지 무료
- 소매 속 에이스: 보스 라운드에 확정한 족보를 한 단계 승급

각 유물은 한 번만 획득할 수 있다. 효과는 코어 상태에서 계산하며 UI는 정의 데이터를 표시만 한다.

### Score and daily run

점수는 처치, 라운드 클리어, 확정 족보, 승리 보너스로 구성한다. 표준 런은 임의 시드, 데일리 런은 로컬 날짜 `YYYY-MM-DD`에서 만든 고정 시드를 사용한다. 프로필은 최고 점수, 최고 라운드, 플레이 수, 승리 수, 데일리 최고 기록을 저장한다.

## Player Experience

첫 화면에서 일반 게임과 오늘의 도전을 선택한다. 첫 게임에는 네 단계 튜토리얼을 표시한다. 전투에는 일시정지와 ×1/×2/×3 배속을 제공한다. 합성 가능 상태, 유물 선택, 고족보, 보스 등장, 승패에는 명확한 시각·음향 피드백을 준다.

키보드는 `E` 교환, `Enter` 확정, `Space` 전투/일시정지, `1`~`3` 배속, `M` 음소거를 지원한다. 모바일 세로 화면에는 가로 모드 안내를 표시한다.

## Persistence

`localStorage` 키는 `poker-defense:v1:profile` 하나를 사용한다. 로더는 누락·손상·구버전 데이터를 기본값과 병합하고 절대로 게임 시작을 막지 않는다. 저장 실패도 게임 진행을 막지 않는다.

## Architecture

- `src/core/relics.ts`: 유물 정의, 결정론 후보 생성, 효과 집계
- `src/core/scoring.ts`: 점수 계산 순수 함수
- `src/core/game.ts`: 합성, 유물 선택, 점수, phase 불변식
- `src/meta/profile.ts`: 프로필 스키마, 저장, 데일리 시드, 업적
- `src/game/MenuScene.ts`: 모드 선택과 기록 표시
- `src/game/AudioManager.ts`: Web Audio 합성 효과음
- 기존 Phaser 렌더러: 합성·유물·점수·튜토리얼·일시정지 UI

코어는 계속 Phaser와 DOM에 의존하지 않는다. 저장과 날짜는 코어 밖 meta 계층에 둔다.

## Quality Gates

- 모든 새 코어 동작은 실패하는 Vitest 테스트를 먼저 작성한다.
- 기존 63개 테스트를 유지한다.
- TypeScript strict 검사와 Vite 프로덕션 빌드가 통과해야 한다.
- 헤드리스 시뮬레이션 100판이 종료되고 클리어율과 라운드 분포를 기록한다.
- 브라우저 스모크는 메뉴 → 시작 → 확정 → 배치 → 전투 경로를 검증한다.

## Explicit Non-goals

서버 계정, 실시간 글로벌 리더보드, 결제, 멀티플레이, 외부 이미지·음원 에셋은 v1.0 범위에서 제외한다.
