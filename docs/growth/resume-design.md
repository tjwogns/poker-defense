# 진행 보호: 이어하기 설계 후보

현재는 구현하지 않았다. 60라운드 모바일 게임에서 진행 보호는 검토 가치가 있지만 실제 이탈 규모는 미측정이다.

## 현재 구조의 위험

기획 에이전트가 `profile.ts`, `game.ts`, `rng.ts`, `PlayScene.ts`를 읽기 전용 검토했다. 프로필은 완료 기록만 저장한다. RNG는 상태를 가진 함수이므로 초기 시드만으로 현재 난수를 복원할 수 없다. 코어에는 Set/Map/Infinity, 보상 큐와 정비 기록 등이 있으며 내기 상태는 PlayScene에 별도로 존재한다. `JSON.stringify(Game)`만으로 저장을 구현하지 않는다.

결과 기록은 호출마다 누적되므로 복원 후 중복 종료를 막아야 한다. 현재 페이지 이탈은 포기, 다시 시작은 새 런으로 집계되며 이어하기에는 동일 런 식별이 필요하다. 일일 도전은 날짜·랭킹·되감기 정책도 별도로 필요하다.

## 권장 첫 범위

일반·왕관 LIFE의 안전한 준비 상태에서 명시적 **저장 후 나가기 / 같은 기기에서 이어하기**. 최초 내기 선택과 보상·정비 처리를 마친 시점만 지원한다. 전투 자동복구, 일일 도전, 클라우드, 복귀 보상은 별도 범위다.

## 구현 전 확정할 수용 기준

- 저장→복원 뒤 같은 입력의 손패·난수·유닛·골드·보상이 중단 없는 실행과 일치한다.
- 홀드/교환/확정/배치 상태를 보존하고 라운드 처음으로 되감지 않는다.
- 내기 보상·결산·왕관 해금·출전/승리 기록은 런당 한 번만 처리한다.
- 저장 실패는 실패로 알리고 정상 저장과 프로필은 보존한다.
- 손상·비호환 저장을 안전하게 거부한다. 새 원정으로 대체할 때 확인한다.
- 복원 시 새 시작 이벤트를 중복 집계하지 않고 휴식과 실제 포기를 구분한다.
- 다중 탭의 오래된 저장이 최신 상태를 덮어쓰지 못한다.
- UI는 안전한 준비 화면으로 재구성한다. 모바일 강제 종료 자동복구까지 보장한다고 표시하지 않는다.

현재 상태: 설계 후보. 이 문서만으로 진행 저장 지원이 완료되었다고 보지 않는다.
