# LIFE 시작 코호트 측정

실행: `npm run analytics:life -- --local --from 2026-09-01 --as-of 2026-09-09`.
버전 기본값은 `CURRENT_VERSION`; 과거 버전은 `--version v2.9.4`로 명시한다. 대상 생략은 도움말만 표시한다. 원격은 `--remote`를 명시한 경우에만 실행하며 이 도구는 SELECT 한 문장만 전송한다. 새 의존성과 서버 배포는 필요 없다.

## 정의

- `--from` 포함, `--as-of` 제외 UTC 자정. 클라이언트 시계 오염을 피하기 위해 모든 순서·기간·D1은 서버 수신 시각 received_at 하나를 기준으로 한다. SQLite 날짜 함수로 정규화하며 해석 불가 수신 시각은 제외된다.
- 보존된 전체 시작 행에서 run_id별 가장 이른 시작을 먼저 선택한 뒤 버전·`life-economy`·시작 기간으로 코호트를 정한다. 동일 run의 이후 이벤트는 시작 이후/as-of 이전만 결합하며 후속 버전 필터를 강제하지 않는다.
- 왕관별 시작·R1 전투 시작·R2 도달을 센다. R2 미도달 중 R1 종료와 R1 이탈만 관측된 런을 구분한다. 이탈은 page-hide 등 신호라 영구 이탈로 확정할 수 없다. 종료 관측도 없는 런은 unresolved로 표시하며 R2 이벤트 없이 이후 라운드 종료가 있는 사례는 품질 집계로 별도 분리한다.
- 첫 실행은 시작 당시 `firstRun` JSON boolean을 우선하고 없는 경우 `tutorialDone` false로 보완한다. 두 값이 불일치하면 품질 집계에 표시한다. HOLD/교환은 선택 행동이므로 빠진 단계를 실패로 추정하지 않는다. 단계별 첫 이벤트의 도달 수와 유효 누적 소요시간 평균을 보고한다. 숫자 타입의 유한한 0 이상 값만 유효하며 숫자 문자열·누락·음수는 평균에서 제외한다. 시간은 단계 간 차이가 아닌 런 시작 후 누적 초다.
- D1은 visitor_hash별 보존된 최초 LIFE 시작이 대상 코호트인 방문자만 대상으로 한다. 그 시작 UTC 날짜 +2일이 as-of 이하인 성숙 표본만 분모에 포함한다. 전체 및 최초 시작의 왕관별로 보고한다. 다음 UTC 날짜의 LIFE `run_started`만 재방문이며 다른 버전은 허용한다. 메뉴 방문·클래식 시작은 제외한다.
- visitor_hash 또는 run_id가 없는 경우 별도 집계하고, 방문자 해시 누락 비율을 표시한다. D1에는 유효 run_id·visitor_hash가 필요하다. 빈 분모의 비율/평균은 null이며 0%로 오해하지 않는다. 왕관 미기록은 unknown으로 분리한다.

## 해석과 안전

동의한 브라우저에서 관측된 이벤트만 포함한다. QA/개발 플레이가 섞일 수 있고 브라우저 변경·저장소 초기화는 다른 방문자로 보일 수 있다. 보존된 첫 LIFE 시작은 실제 신규 사람이 아니며 90일 보존 정책 때문에 과거 방문자가 신규처럼 보일 수 있다. 데이터만으로 사용자 전체·인과효과·제품 시장성을 판단하지 않는다.

출력은 집계값만 포함하고 원시 visitor/run/session ID를 내보내지 않는다. 오류 시 원격 원문도 출력하지 않는다. 원격 데이터에 쓰기·삭제·마이그레이션을 수행하지 않는다. 테스트는 실제 마이그레이션을 적용한 임시 SQLite fixture만 사용하며 원격 조회를 실행하지 않는다.
