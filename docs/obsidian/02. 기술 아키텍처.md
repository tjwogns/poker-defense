# ⚙️ 02. 기술 아키텍처

> TypeScript strict + Vite + Phaser 3.90 + Vitest. 게임 규칙, 브라우저 메타 상태, 렌더링을 분리한다.

## 📁 구조

```text
src/core/                  Phaser·DOM 의존성 없는 결정론 게임 코어
  cards/                   덱, 교환, 족보 판정
  combat.ts                고정 틱 전투와 유닛 특성
  game.ts                  phase, 경제, 합성, 유물, 점수, 승패
  relics.ts                유물 정의·후보 생성·효과 집계
  scoring.ts               점수 순수 함수와 RunSummary
src/meta/profile.ts        localStorage 스키마·복구·업적·데일리 시드
src/game/
  MenuScene.ts             일반/데일리 시작과 기록
  PlayScene.ts             입력·상태 동기화·종료 기록
  FieldRenderer.ts         필드·유닛·적·이펙트
  HandBar.ts               카드 조작
  SidePanel.ts             경제·합성·배속·상태 UI
  TutorialOverlay.ts       첫 판 온보딩
  AudioManager.ts          Web Audio 합성 효과음
src/sim/run.ts             합성·유물 전략을 사용하는 헤드리스 봇
tests/                     코어·메타 Vitest 81개
scripts/smoke.mjs          Chrome E2E와 스크린샷
```

## 🧠 설계 원칙

| 원칙 | 구현 |
| --- | --- |
| 결정론 | mulberry32 시드 RNG와 30Hz 고정 틱 |
| 공정한 데일리 런 | 날짜 해시 시드, 유물 후보는 시드+마일스톤으로 별도 생성 |
| UI와 규칙 분리 | Phaser는 Game 공개 API만 호출 |
| 데이터 주도 | 밸런스·유닛·적·유물 정의를 별도 모듈에서 관리 |
| 방어적 저장 | 손상·누락 localStorage는 기본 프로필로 복구 |
| 무에셋 실행 | 그래픽은 Phaser 벡터, 사운드는 Web Audio로 생성 |

## 🧪 품질 게이트

- Vitest 9개 파일, 81개 테스트
- TypeScript `strict`, 미사용 변수·파라미터 검사
- 일반 Vite 빌드와 단일 HTML 빌드
- 100판 결정론 밸런스 시뮬레이션
- Chrome E2E: 메뉴 → 튜토리얼 → 족보 확정 → 배치 → 전투 → 보스 유물 선택

## 💾 프로필 스키마

키: `poker-defense:v1:profile`

```text
version, totalRuns, wins, bestScore, bestRound,
tutorialDone, soundEnabled, achievements[], daily{date,bestScore}
```

저장 실패나 잘못된 JSON은 게임 실행을 중단하지 않는다.

## ⌨️ 입력

- 마우스/터치: 카드, 버튼, 타일
- `E`: 교환
- `Enter`: 족보 확정
- `Space`: 전투 시작/일시정지
- `1`~`3`: 전투 배속
- `M`: 음소거
