# 포커 디펜스: Royal Siege

포커 족보로 유닛을 뽑아 순환 경로를 도는 적을 막는 웹 디펜스 게임.
카드 조합, 군단 성장, 순환형 전장을 결합한 독립 오리지널 프로젝트다.

## v1.2 Royal Table UI

- 우측 정보를 상태·경제·군단·컨트롤·스킬·유물·도움말의 7개 고정 구획으로 분리해 텍스트 겹침 제거
- 보스 HUD를 필드에서 상태 패널 내부로 이동
- 카드 앞/뒤 코너 표기, 잠금 강조, 전용 핸드 트레이 추가
- 필드 타일 깊이감, 경로 마커, 유닛 선택 링, 적 타입별 실루엣과 보스 문장 강화
- 비활성/활성 버튼 대비, 그림자·하이라이트·호버 피드백 개선

## v1.1 Breakout 핵심

- **3기 합성**: 같은 등급 유닛 3기 → 한 단계 위 유닛
- **유물 빌드**: 보스 격파마다 결정론적 3지선다, 판마다 다른 성장 전략
- **무늬 액티브**: 확정한 패의 주 무늬를 충전해 전체 타격·퇴장·골드·기절 스킬 사용
- **고유 보스 6종**: 철갑 딜러부터 로열 조커까지 10라운드마다 다른 공략
- **오늘의 도전**: 날짜별 고정 시드와 데일리 최고 점수
- **공유와 기록**: 결과 텍스트·PNG 카드·데일리 도전 링크, 최근 20판 JSON 로그
- **익명 플레이 분석**: 동의 기반 진행·이탈·재도전 이벤트, DATA ON/OFF, 로컬 로그 내보내기
- **기록과 업적**: 최고 점수·라운드·승리·6개 업적을 브라우저에 자동 저장
- **온보딩과 피드백**: 첫 판 튜토리얼, 합성·유물·보스·승패 사운드와 연출
- **빠른 조작**: `E` 교환 · `Enter` 확정 · `Space` 전투/일시정지 · `1/2/4` 배속 · `Q/W/R/T` 스킬 · `H` 족보·유닛 도감 · `M` 음소거

## 실행

```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm test           # 코어 로직 단위 테스트 (vitest)
npm run sim -- 30  # 헤드리스 밸런스 시뮬레이션 30판
npm run build      # 타입체크 + 프로덕션 빌드 (dist/)
SINGLEFILE=1 npm run build  # 단일 HTML 파일 빌드 (배포/공유용)
node scripts/smoke.mjs      # E2E 스모크 (Chrome 필요, 프리뷰 서버 선행)
```

## 게임 규칙 요약

- 매 라운드 카드 5장 드로우 → 홀드 후 교환(무료 1회, 추가는 골드) → **족보 확정 = 그 등급의 유닛 획득** (하이카드도 최하급 유닛 지급)
- 유닛을 타일에 배치하면 자동 공격. 적은 죽을 때까지 사각 경로를 순환
- **필드의 적이 80마리를 넘으면 패배**, 60라운드를 버티면 승리. 10의 배수 라운드는 보스
- 골드 사용처: 추가 교환(도박) vs 전역 공격력 강화(확정) vs 유닛 판매/재배치

## 구조

```
src/core/   순수 TS 게임 로직 — Phaser 의존성 0, 고정 틱(30/s) 결정론 시뮬레이션, 시드 RNG
            (cards/ 덱·족보판정, combat 전투, game 상태머신, balance 모든 수치)
src/game/   Phaser 3 렌더링/입력 — core 상태를 그리기만 한다
src/meta/   프로필·공유·동의 기반 익명 플레이 분석
src/sim/    헤드리스 밸런싱 시뮬레이터 (core만 import)
tests/      vitest 단위 테스트 (core 전체)
```

밸런스 수치는 전부 `src/core/balance.ts` 한 파일에서 관리한다.
밸런스 결과는 `npm run sim -- 100`으로 재현하며, 공개 테스트 데이터와 함께 릴리스마다 다시 기록한다.

## 익명 플레이 분석

- 최초 실행 시 사용자가 허용한 경우에만 이벤트를 기록한다.
- 기록 이벤트: 시작·튜토리얼·족보 확정·첫 전투·주요 라운드·무효 배치·합성·유물·종료·이탈·재도전·공유
- 이름, 이메일, 실제 카드 내용은 이벤트에 넣지 않는다.
- 기본 상태에서는 최근 500개 이벤트를 브라우저에만 저장하고 `LOG EXPORT`에 포함한다.
- 중앙 수집이 필요하면 HTTPS POST 수집 주소를 저장소의 GitHub Actions 변수 `VITE_ANALYTICS_ENDPOINT`로 설정한다. 요청 본문은 `{ schema: "poker-defense-event-v1", event: ... }` 형식이다.
- 수집 주소는 CORS와 `sendBeacon` 요청을 허용해야 한다. 로컬 개발에서는 `.env.example`을 복사해 같은 변수를 설정할 수 있다.
- 공개 안내문은 `/privacy.html`에 포함된다.
